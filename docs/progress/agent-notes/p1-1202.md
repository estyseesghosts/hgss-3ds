## Deviation 1 (brief said `#define favoriteColor favouriteColour` — not used)
`grep` shows the brief's zero-collision condition FAILS: OSOwnerInfo.favoriteColor
(nitro/os/ownerInfo.h:13), wifi_setup_share.h:174 (`u8 favoriteColor : 4`), and in the port
nitro_port.h:208 + platinum.h:38. Worse, os_ownerInfo.c (compiled into the port via nitro
Makefile:103) includes both headers through nitro.h and touches `info->favoriteColor`
(OSOwnerInfo) and `src->ncd.owner.favouriteColour` (NVRAM) in ONE TU — the #define would
rewrite line 10 to `info->favouriteColour`, which does not exist. Any TU mixing include
orders breaks the same way. Used whole-run anonymous unions instead (both spellings live,
zero effect on any other struct). First cut wrapped only the one Option bitfield — that
splits the run into three storage units (the exact pitfall the brief warned about); fixed
to repeat the full 16-bit run, second struct using unnamed (:11/:4) padding so no member is
declared twice (ambiguous access would break os_ownerInfo.c's `.language` etc.).

## Deviation 2 (brief said `PXI_SetFifoSendCallback(int fifotag, ...)` — not used)
pxi.c:113 defines it with ONE argument (`(PXIFifoEmtpyCallback callback)`); nobody calls it.
A two-argument declaration would itself be a conflicting-types error — the exact class this
slice removes. Declared the one-argument form; the header comment says so.
