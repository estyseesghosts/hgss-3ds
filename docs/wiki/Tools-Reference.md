# Tools reference

Every script in `tools/` and every test runner in `tests/`, with what it does, how to call it, and what it needs. Usage lines are copied from each script's header. Where a header and the code disagree, the entry says so.

Terms used below:

- **Container**: the dev container. Run with `devcontainer exec --workspace-folder . bash -c 'cd /workspaces/pokeheartgold-3ds && ...'`. See [Getting-Started](Getting-Started.md).
- **MWCC**: the proprietary Metrowerks compiler. It lives in your `~/hgss-private/mwccarm/` and reaches the decomp checkout through `tools/install-ds-toolchain.sh`.
- **ROM**: your own game ROM. Nothing in this table needs one unless it says so.

Dot-named files in `tools/` (for example `tools/.gate.sh`) are local scratch. `.gitignore` excludes `tools/.*`, so they are not part of the repository and are not documented here.

## Tools

### `tools/bootstrap.py`

Fetches the decomp at the commit in `upstream.lock` into `build/upstream/` and applies the patch stacks as commits.

- **Usage:** `python3 tools/bootstrap.py [--clean]`
- **Reads:** `upstream.lock`, `patches/NitroSDK/*.patch`, `patches/NitroSystem/*.patch`, `patches/pokeheartgold/*.patch`.
- **Writes:** `build/upstream/`, the symlinks `build/NitroSDK` and `build/NitroSystem`, and `build/upstream/lib/include/nitro/fx/fx_const.h` (generated by the decomp's own host tool, if present).
- **Needs:** the container (git, make, gcc). Network access for the first fetch from GitHub. No MWCC, no ROM.
- **Behaviour to know:**
  - With no `--clean`, it does nothing if the checkout is at the pin and the number of applied commits equals the number of patch files. It prints `upstream: already at <commit> with N patches`.
  - It compares patch counts, not contents. Editing an existing patch does not re-apply it. Use `--clean` after any patch edit.
  - `--clean` deletes `build/upstream/` and the two SDK symlinks, then fetches again.
  - Any patch that does not apply stops the run and prints the `git am` output.

### `tools/hgss_nitro.py`

Builds the vendored `3ds_port` libraries and runs their tests against HGSS's SDK without editing the vendored Makefiles. It creates shims under `build/hgss-sdk` and `build/hgss-nns` (source symlinks, filtered include dirs, a stand-in `fx_const` generator) and passes `SDK=`, `SDK_SRCS=`, `SDK_INCLUDES=`, `ARM7_SOUND_SRCS=`, `NNS=`, `NNS_SRCS=` and an optional `OUT=` to make.

- **Usage:** `python3 tools/hgss_nitro.py {shim|make|list} [--root build/upstream] [--target host32] [--out DIR] [--subproject {pak,nitro,nitrosystem,all}] [-- make args]`
- **Reads:** the patched tree at `--root` (default `build/upstream`), `hgss/compat/include`, `hgss/compat/src`, `sub/lib/src` and the vendored `3ds_port`.
- **Writes:** `build/hgss-sdk/`, `build/hgss-nns/`, `build/hgss-res/` (hard links to the game files `test_nitrosystem` walks) and objects under `--out`.
- **Goals:** `lib` builds `libnitro.a`; `test` runs the selected subprojects (default all three). `make port-tests` calls `test`.
- **Output:** the vendored build's status. `lib` currently builds with 0 errors; `test` passes every suite except `test_arm7`'s `test_sound`.
- **Needs:** the container, after bootstrap. gcc-10 (`CC` in the image). No MWCC, no ROM.
- **Notes:** always pass `--out` for a private tree; `-k` shows every failing file. `list` prints the compiled lists and the excluded files. Every compile force-includes HGSS's MSL `assert.h` and `hgss/compat/include/hgss_port_math.h` (see [Build-Reference](Build-Reference.md#7-how-the-vendored-port-build-is-wired)).

### `tools/game_sources.py`

Reads HGSS's `Makefile`, `common.mk`, `filesystem.mk` and `main.lsf` and emits the game source list.

- **Usage:** `python3 tools/game_sources.py [--root build/upstream] {--game-sources|--c-sources|--cpp-sources|--asm-sources|--lib-sources|--port-lib-sources|--overlay-map|--json}`
- **Reads:** the checkout at `--root`. No ROM, no MWCC.
- **Output:** lists, or JSON (1012 C, 56 C++, 150 ARM9 `.s`, 259 port-lib sources, 129 overlays) and the object→source→overlay map.
- **Tested by:** `tests/test_game_sources.py` (synthetic trees; the real tree in a skip-guarded case).

### `tools/game_overlays.py`

Turns `main.lsf` into the overlay table and section plan the port uses.

- **Usage:** `python3 tools/game_overlays.py [--root ...] [--table FILE] [--ids-output FILE] [--header FILE]`
- **Output:** `gHeartgoldOverlays` for `NitroPort_SetOverlays`, the `SDK_OVERLAY_*` linker script, the `SDK_PORT_OVERLAY_ID_*` header, and an objcopy section plan that renames `.data`/`.bss`/`.sinit` (and GCC's `.init_array`) per overlay so C++ constructors run on overlay load, not at startup.
- **Tested by:** `tests/test_game_overlays.py` (129 overlays, `OVY_45`'s C++ objects, ELF section renaming).

### `tools/prepare_game_headers.py`

Generates every build-time header the game needs, without MWCC or a ROM.

- **Usage:** `python3 tools/prepare_game_headers.py [--root build/upstream] [--ids-output FILE] [--header FILE]`
- **Output:** `lib/include/nitro/fx/fx_const.h`, `files/msgdata/msg/msg_0729.gmm`, 828 `msg_*.h`, 205 `.naix`, and optionally the overlay IDs. It is a pure-Python port of `gen_fx_consts`, `msgenc -H`, `nitroarc --index-namespace`, `o2narc` and `csv2bin --naix`.
- **Proven by:** byte-for-byte identity against `/work/pokeheartgold`'s matching build; `tests/test_prepare_game_headers.py`.

### `tools/s_to_gas.py`

Converts HGSS's MWAS `.s` files to GAS and optionally assembles them.

- **Usage:** `python3 tools/s_to_gas.py --root <checkout> <input.s> -o <out.s|out.o|-> [--cc CC] [--cflags ...]`
- **Does:** recursive `.include`, `#define`/`FS_EXTERN_OVERLAY` expansion, escape-aware `;` comments, `.public`→`.global`, MWAS `.section`→GAS sections + alignment, `.word`→`.4byte` (x86 `.word` is 16-bit), and `cw.inc`'s `exception` macro.
- **Proven by:** all 150 ARM9 `.s` assemble under `gcc-10 -m32` and `arm-none-eabi-gcc -march=armv6k` with no symbol/section/alignment difference; `tests/test_s_to_gas.py`.

### `tools/make_game_wifi_stubs.py`

Generates "not implemented" C for the network symbols game objects reference.

- **Usage:** `python3 tools/make_game_wifi_stubs.py --nm NM --headers DIR... --sources SRCS... --output FILE OBJS...`
- **Does:** scans undefined symbols matching `^(DWC|DWCi|PPW|VCT|WVR|SOC|SOCL|WCM|CPS|NHTTP)_`, logs once, returns the SDK's not-available code, and keeps 64-bit returns 64-bit. HGSS overrides: `WVR_StartUpAsync`/`WVR_TerminateAsync` call the callback with `result 0` and return 1, `DWC_Init` returns 0.
- **Tested by:** `tests/test_game_stubs.py`.

### `tools/hgss_game.py`

Compiles the game and links a target. See [Build-Reference](Build-Reference.md#3-what-can-be-built-today) and [phase-2.md](../progress/phase-2.md).

- **Usage:** `python3 tools/hgss_game.py --target {host32,3ds} [--keep-going] [--out DIR] [-- {make args}]`
- **Does:** runs `prepare_game_headers.py`, compiles `src/**/*.c|*.cpp` plus the port-compiled `lib/` sources, assembles the `.s` files, builds `libnitro.a`/`libnitrosystem.a`, writes the overlay table and ID script, generates the Wi-Fi stubs, and links `build/pokeheartgold-pc` or a 3DS static link.
- **Output:** object counts, per-file errors and the full unresolved-symbol list. Today: 1092/1092 compile, 150/150 `.s`, **linked with 0 unresolved** for both targets; the 3DS target also packages `pokeheartgold.3dsx` (with an SMDH) and then runs `validate_3dsx()`, which fails the build if a 3DS loader would reject the file (see [3DS-Pitfalls](3DS-Pitfalls.md)).
- **Needs:** the container. The 3DS target needs devkitARM (present).
- **Tested by:** `tests/test_hgss_game.py`.

### `tools/boot_smoke.py`

Tells you *where* a boot stopped, for a scripted or unattended run.

- **Usage:** `python3 tools/boot_smoke.py --pc build/pokeheartgold-pc [--pak P] [--manifest M] [--frames N] [--json]`
- **Does:** runs the program briefly and classifies the outcome: `missing_file` (with the NitroFS path the game asked for), `stall`, `exception`, `crash`, or `frame_limit`, plus a `boot_stage` (e.g. `overlay:intro_title`).
- **Output:** a JSON report (and a human summary without `--json`); exit 0 when the run is understood, non-zero when it is not.
- **Needs:** the container. A pack and manifest for anything past the first file request.
- **Tested by:** `tests/test_boot_smoke.py` (synthetic packs).

### `tools/frametime_report.py`

Turns the shells' `FRAMETIME` lines into the performance budget table.

- **Usage:** `python3 tools/frametime_report.py [LOG …] [--json OUT] [--markdown OUT]` (no argument reads stdin).
- **Does:** parses `FRAMETIME frame=N logic_us=… draw_us=… audio_us=… total_us=…`, ignoring every other line, so a whole `log.txt` can be passed.
- **Output:** mean/min/p95/max per subsystem, the frame rate against the 60 Hz target, and the count of frames over 16.7 ms. `draw_us` includes the flip wait; `total_us` is what decides whether it feels smooth.
- **Needs:** nothing but Python.
- **Tested by:** `tests/test_frametime_report.py`.

### `tools/check_repo_content.py`

Fails if the tracked index contains game content, a build artifact or an oversized file; the pre-push and CI content gate.

- **Usage:** `python3 tools/check_repo_content.py [--root DIR] [--max-bytes N]` (or `make content-check`).
- **Does:** reads `git ls-files`, rejects ROM/save/pak/`.3dsx`/`.smdh`/CIA/dump/archive/build paths, and only allows the three original icons/chime in the tree.
- **Output:** a one-line pass, or one line per offending path; exit 1 on any.
- **Needs:** a git checkout; no decomp, ROM or toolchain.
- **Tested by:** `tests/test_repo_content.py`.

### `tools/golden/run.py`

Replays a scene through the PC build and diffs the screens against a reference.

- **Usage:** `python3 tools/golden/run.py --scene NAME [--reference DIR] [--no-run --run DIR] [--out DIR]`
- **Does:** runs the scene (`tests/inputs/NAME.txt`), aligns it to the reference on the first matching frame, and compares every overlapping frame: 2D exact, 3D within 8/255 per channel up to `--3d-until`.
- **Output:** `report.json`, `report.html` and one PNG heat map per differing frame. Without a reference it writes a regression baseline and says the melonDS comparison is still pending.
- **Needs:** the container and a pack for the capture step; `--no-run` needs neither.
- **Tested by:** `tests/test_golden_run.py` (synthetic PNGs only).

### `tools/symbol_crosscheck.py`

Compares the linked PC program's global C-named symbols against the DS reference ELF. Every symbol the
DS build defines must be present in the PC ELF, or listed with a reason in
`tools/symbol_crosscheck_allowlist.txt`. A missing symbol means a source file was left out of the PC
build, so this is the convergence signal for the unresolved-symbol work.

- **Usage:** `python3 tools/symbol_crosscheck.py [--pc build/pokeheartgold-pc] [--reference ELF] [--no-build-reference]`
- **Reference:** `build/reference/main.elf`, then `/work/pokeheartgold/build/heartgold.us/main.elf`, then
  the SoulSilver ELF; `--no-build-reference` skips `tools/matching-build.sh`.
- **Output:** matched / allowlisted / missing counts and the missing set; exit 1 on any missing symbol.
  `--help` works without pyelftools (it is imported only when an ELF is read).
- **Tested by:** `tests/test_symbol_crosscheck.py` (synthetic symbol tables).

### `tools/install-ds-toolchain.sh`

Copies your MWCC and Nitro SDK files into the decomp checkout, at paths that git ignores.

- **Usage:** `tools/install-ds-toolchain.sh [DECOMP_DIR] [PRIVATE_DIR]`. Defaults: `/work/pokeheartgold` and `$HGSS_PRIVATE` or `/private`.
- **Reads:** `PRIVATE_DIR/mwccarm/` (needs `2.0/sp2p2/mwccarm.exe`, `2.0/sp2p3/mwccarm.exe` and `license.dat`), and `PRIVATE_DIR/NitroSDK/` (needs `tools/bin/makelcf.exe` and the three `include/nitro/specfiles/*.template` files).
- **Writes:** `tools/mwccarm/`, `tools/bin/`, `sub/ARM7-TS.lcf.template`, `ARM9-TS.lcf.template` and `mwldarm.response.template`, all inside `DECOMP_DIR`. It converts the two LCF templates from cp932 to UTF-8 if they are not already UTF-8.
- **Also:** runs `mwccarm.exe` once under Wine as a smoke test, with `LM_LICENSE_FILE` pointing at the copied `license.dat`.
- **Refuses:** to run if `DECOMP_DIR` is not a git checkout, or if a destination is not git-ignored there. It never writes to the private folder.
- **Needs:** the container (wine, xvfb-run). MWCC and the SDK files in the private folder. No ROM.

### `tools/matching-build.sh`

Builds the pinned decomp for one version and checks it is still byte-identical to the retail ROM.

- **Usage:** `tools/matching-build.sh [DECOMP_DIR] [HEARTGOLD|SOULSILVER]`. Default `DECOMP_DIR` is `/work/pokeheartgold`.
- **Writes:** `build/heartgold.us/` or `build/soulsilver.us/` inside `DECOMP_DIR`. The ROM is `pokeheartgold.us.nds` or `pokesoulsilver.us.nds` in that folder. The script adds five `KEEP_SECTION` blocks to the generated `main.lcf` (the linker script) when they are missing. Phase 0 found that without them the linker drops sections the retail ROM keeps.
- **Check afterwards:** `sha1sum -c` against the SHA1 in [Getting-Started](Getting-Started.md#7-run-the-matching-build).
- **Needs:** the container, MWCC and the SDK installed by `install-ds-toolchain.sh`. No ROM as input. The output ROM contains game code: keep it in `/work` and never copy it into the repo.
- **Time:** Phase 0 measured about 18 minutes for the first full HeartGold build and about 3 minutes for a relink (Apple silicon, Rosetta, `-j10`). See [docs/progress/phase-0.md](../progress/phase-0.md).

### `tools/sdk_compile_survey.py`

Syntax-checks every `lib/NitroSDK/src` and `lib/NitroSystem/src` source with GCC, using the port's flags and `-DSDK_PORT_3DS`. It is the Phase 1 progress measure.

- **Usage:** `python3 tools/sdk_compile_survey.py [--root build/upstream] [--lib NitroSDK|NitroSystem|all] [--m32] [-j N] [--json OUT] [-v]`
- **Reads:** the patched tree in `build/upstream`, which must contain the generated `fx_const.h` (bootstrap makes it).
- **Writes:** nothing, except the file named by `--json`.
- **Output:** a summary line such as `270/284 files parse; 14 fail; N warnings` with the default gcc 13, or `269/284; 15 fail` with `--gcc gcc-10`. `-v` shows the first errors. Exit status is 1 while any file fails.
- **Needs:** the container. No MWCC, no ROM.
- **Also run as:** `make sdk-survey`.

### `tools/port_compile_survey.py`

Checks how far the vendored `3ds_port/nitro/src` is from compiling against the HGSS headers. It does not edit the vendored code.

- **Usage:** `python3 tools/port_compile_survey.py [--root build/upstream] [--shim build/hgss-shim]`
- **Writes:** symlinks in `build/hgss-shim/include/` that expose only `nitro`, `nnsys` and `cw` from `lib/include`.
- **Output:** the count and the grouped first errors. Exit 0 only if every file compiles. Last run: `46/46`, exit 0.
- **Note:** the header says `[--no-pak]`. The script does not accept that flag.
- **Needs:** the container, after bootstrap. No MWCC, no ROM.

### `tools/sdk_inventory.py`

Lists which files the HGSS SDK tree has that the Platinum SDK tree does not, and the other way round, and counts differing lines for files with matching names. It does not decide whether a difference matters. [docs/sdk-diff.md](../sdk-diff.md) records those decisions.

- **Usage:** `python3 tools/sdk_inventory.py HGSS_DECOMP_DIR PLATINUM_NITROSDK_DIR`
- **Reads:** a decomp checkout and a NitroSDK tree from pokeplatinum-3ds's subprojects. This repo does not vendor that tree; you must supply it.
- **Writes:** stdout only.
- **Note:** the header mentions `--sys NITROSYSTEM_DIR`. The code reads only the first two arguments and ignores the option.
- **Needs:** no container, no MWCC, no ROM.

### `tools/savetool.py`

Normalizes, validates and diffs save images. The format it checks is described in the script's header (slot layout, footer, CRC).

- **Usage:**
  - `savetool.py normalize IN [-o OUT]`: strips a DeSmuME footer and checks the size. Writes a file only with `-o`. Without it, it prints `ok: N bytes`.
  - `savetool.py validate FILE [--layout SIZE0,SIZE1]`: checks both slot footers and CRCs, and prints the status and the newer mirror. Exit 0 only when the status is `IS_GOOD`.
  - `savetool.py diff A B [--block 4096]`: prints the byte ranges that differ.
- **Reads:** a save file. Use your own saves, or synthetic ones in tests.
- **Needs:** Python 3 only (standard library). It does not need the container, MWCC or a ROM. Its unit tests are in `tests/test_savetool.py`.

### `tools/rom_compare.py`

Compares two NDS ROMs region by region, and maps differing bytes in the decompressed ARM9 to symbols. It was how Phase 0 found the dead-stripped sections.

- **Usage:** `python3 tools/rom_compare.py REFERENCE.nds BUILT.nds [--elf main.elf]`
- **Reads:** two ROM files. The reference must be your own dump. The script prints counts and symbol names, not contents.
- **Writes:** stdout only.
- **Needs:** your reference ROM. `--elf` calls `arm-none-eabi-nm`, which is in the container.

### `tools/qsort_rom_oracle.py`

Checks the C version of `MATH_QSort` (patch 0801) against the original ARM machine code of the retail ROM, run in the `unicorn` emulator.

- **Usage:** `qsort_rom_oracle.py ARM9_DECOMPRESSED.bin MAIN_ELF PATCHED_ROOT`
- **Reads:** a decompressed ARM9 binary from your own ROM. The script does not make that file; `tools/rom_compare.py` contains the BLZ decoder it needs. Also the `main.elf` from a decomp build, and the patched tree.
- **Writes:** nothing in the repo. It compiles a harness in a temp directory and prints `N cases, M comparator calls compared, K mismatches`. Exit 1 on any mismatch.
- **Needs:** your ROM, the `unicorn` Python package (not in the image; install it in a venv), and the container.
- **Status:** not run in this session. Phase 1 records 465,985 comparator calls matching, from an earlier run ([docs/progress/phase-1.md](../progress/phase-1.md)).

### `tools/nns_inline_symbols.py`

Writes a C file that includes every NitroSystem header, so the vendored NitroSystem build can mark GCC's inline copies as weak.

- **Usage:** `python3 tools/nns_inline_symbols.py OUTPUT.c`
- **Reads:** `build/NitroSystem/include/nnsys` and `build/NitroSystem/libraries/*/include` (Platinum's layout).
- **Status for HGSS:** not used yet. Only the vendored `3ds_port/nitrosystem/Makefile` calls it, and that Makefile is not wired to HGSS. On the HGSS tree the script exits with `build/NitroSystem not found`, because `build/NitroSystem` has no `include/` directory. The message is misleading, but the cause is the layout.

### `tools/layout_probe/run_probe.py` (and its helpers)

Compares `sizeof` and `offsetof` for the save-chunk struct types under GCC against the MWCC reference committed in `tools/layout_probe/mwcc.txt`. Run it through `tests/layout_probe/run.sh` (see the test runners below).

- **Usage:** `run_probe.py --root build/upstream [--decomp /work/pokeheartgold] [--files DIR] [--update-mwcc] [--variants g32,g32d,arm] [--work DIR]`
- **Default variants:** `g32` (`gcc -m32`), `g32d` (`-m32 -malign-double`), `arm` (devkitARM with the 3DS flags).
- **Needs:** pyelftools (in the image). A decomp checkout with generated `.naix` headers under `files/` (run `make` there once, or pass `--files`). MWCC and Wine are needed only with `--update-mwcc`, which rewrites the committed reference. Do not run that casually.
- **Work directory:** defaults to `/tmp/layout_probe` inside the container.
- **Helpers in the same folder:**
  - `gen_probe.py`: `types DECOMP OUT.c` writes the types translation unit. `probe TYPES.o OUT.c OUT.names` walks the DWARF and writes the probe array.
  - `roots.py`: `roots.py DECOMP_DIR` lists the 45 save-chunk root types from `src/save_arrays.c`.
  - `compare.py`: `compare.py extract OBJ.o NAMES` and `compare.py diff A.txt B.txt`.
- **Last run:** 804 values, 0 differences for each of the three GCC variants.

### `tools/golden/capture.lua`

BizHawk script that drives the game with a frame-indexed input file and saves a PNG for each captured frame. This is how the golden reference frames are meant to be made.

- **Usage:** from BizHawk's Lua console, `SCENE = "boot-title"; dofile("tools/golden/capture.lua")`. The header describes the command-line form.
- **Reads:** `tests/inputs/<scene>.txt` and your ROM, loaded in BizHawk.
- **Writes:** `tests/golden/<scene>/<frame>.png`. That folder is git-ignored because it shows game art.
- **Needs:** BizHawk, which has no macOS build (see [tools/golden/README.md](../../tools/golden/README.md)), and your US HeartGold or SoulSilver ROM.
- **Status:** never run. The touch button names are unverified, and the input scripts are uncalibrated. [Phase 0](../progress/phase-0.md) lists this as not done.

### `tools/golden/compare_runs.py`

Determinism check: compares two capture folders pixel by pixel.

- **Usage:** `python3 tools/golden/compare_runs.py DIR_A DIR_B`
- **Output:** one line per difference, then `N frame(s) compared, M problem(s)`. Exit 0 if identical, 1 if different, 2 on a usage error.
- **Needs:** Pillow (in the image). No ROM. Its input is the PNG folders from `capture.lua`.
- **Status:** checked in this session on two synthetic 4×4 PNG folders. Identical folders exit 0, and one changed pixel exits 1.

Notes:

- The SDK runners take `[ROOT]`, which defaults to `build/upstream`, or a patched tree. `make test` passes `build/upstream`. Most runners compile with `-m32 -malign-double` and the flags of `tools/sdk_compile_survey.py`. `nns_clz` and `small` keep their own flag lists in the script. Each runner prints its own pass or fail lines and exits non-zero on failure.
- `make test` runs `tool-tests` (the Python files under `tests/`, **338 tests in all**) and then each `tests/sdk/*/run.sh` (**20 suites**). Last run: exit 0.
- `tests/sdk/port_memory.c` is a helper, not a suite: it defines the eleven port memory arrays for the suites whose SDK objects touch registers or main memory (patches 1301/1302). A test that needs them links it from its `run.sh`.
- `tests/layout_probe/run.sh` reads `PY` (Python with pyelftools; default `python3`), `DECOMP` (default `/work/pokeheartgold`) and `FILES` (default `$DECOMP/files`). Extra arguments are passed to `run_probe.py`.
- `tests/inputs/*.txt` are the frame-indexed input scripts (`boot-title`, `main-menu-nosave`, `newgame-buttons`, `newgame-touch`) for the PC runner and the 3DS `script.txt`. They are calibrated against the PC run; a melonDS capture is still open.
- The vendored `3ds_port/` builds and tests through `tools/hgss_nitro.py`; `make port-tests` is **green at 79 patches** (exit 0, nitrosystem 17,122 checks). See [docs/port-wiring.md](../port-wiring.md).
