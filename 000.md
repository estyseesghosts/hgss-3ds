### Standard of work

The last sessions lost most of their time to avoidable errors: a throttle built on a counter already recorded as wrong, a fast path that was correct and never executed, timings quoted from a stage that was not the wall. This plan exists so that does not happen again. Hold yourself to these:

- **Know what bounds the metric before you cut anything.** Name the thread, the core and the counter. If you cannot, you are not ready to change code.
- **Prove the path runs.** A change is not done until a counter in the target scene shows the new path taken and the old work absent. A green test is not that proof.
- **One hypothesis per change, one change per commit.** Write the claim sheet (`docs/bench/claim-sheet-template.md`) before the code, including what result would make you revert.
- **Read the code you are changing end to end**, including every caller and everything that reads the state you touch. Line numbers in this plan are from `5f5a6d2`; resolve the symbol, do not trust the number.
- **Report negative results plainly.** "Neutral, reverted" is a good outcome. A kept change with no measured effect must be labelled as such.
- **Do not widen scope.** No refactors, no renames, no new subsystems, no new ini knobs beyond the ones named here.
- **Stop and ask** when a stop condition below is hit. Do not guess past it.

- Report window: frames 9000 and later, as in the existing claims.
- Report with `tools/bench_report.py --check-manifest`.

### What counts as progress

Emulator milliseconds are not hardware milliseconds. A change is accepted on these, in this order:

1. **Activation:** a counter shows the new path taken in both scripts.
2. **Work removed:** a counter of real work per 600 ticks drops (bytes hashed or walked, pixels decoded, lists scanned, vertices transformed, composes submitted, lines copied). State the number before and after.
3. **Throughput in Azahar, GPU timings on:** game ticks per wall second do not fall, and built scenes/s, unique composes/s or drawer passes/s rise by more than the spread between trials. Overlapping ranges are "inconclusive", and you say so.
4. **OFF agrees:** the OFF build moves the same direction.
5. **Correctness:** the packet's own check passes, `make port-tests` and `make tool-tests` show no new failure, and captures at fixed script frames are unchanged from baseline.

To translate work removed into an expected hardware effect, use only costs measured on hardware in `log-0` (for example, a 304 KB VRAM hash cost about 6.4 ms there). Label every such figure as a prediction.

## 3. Work packets

Each packet lists what to do, what to hand back, what to avoid, and when to stop. Packets P1 and P2 come first because every later decision depends on them.

### P0 — Reproduce the baseline

**Do.** Configure Azahar as above. Build PROFILE and OFF at `5f5a6d2` with default flags. Run both scripts, 3 trials each. Attach GDB once: break on `NitroPort_Render2DSplitIfChanged`, print the engine argument, continue. Read one counter over RPC.

**Deliver.** A baseline table (ticks/s, composes/s, publishes/s, drawer passes, scene-draws, geometry done and skipped, GPU ms) with per-trial spread, and a note on GDB-stub start behaviour.

**Avoid.** Changing any source. Changing `cpu_clock_percentage`.

**Stop if** Azahar's field numbers differ wildly between identical trials (spread above about 15%); fix the run procedure before continuing.

### P1 — Make the numbers true (instrumentation only, PROFILE build only)

No rendering, scheduling or pixel behaviour may change. Every addition compiles to nothing under `HGSS_PROFILE_OFF`. No logging, formatting or locking inside inner loops; accumulate in plain counters and print in `PerfLog`.

**Do.**

1. **Geometry counters** (`3ds_port/nitro/src/port_gx3d.c`, `hgss/game/app/main_3ds.c` `PerfLog`). Count built and skipped scenes separately and accumulate worker ticks separately for each. Print `built N (ms/built), skipped M (ms/skipped)`. Keep the old fields so `bench_report.py` still parses old logs.
2. **Core accounting** (`main_3ds.c`). Make the existing idle probes (the `HGSS_A0_DIAG` spin threads and calibration) part of the PROFILE build on Old 3DS, and print idle % for core 0 and core 1 each sample. Add game-thread accounting: ticks from `NitroPort_OnFrame` entry to the frame-cap call, ticks slept in `WaitForFrameCap`, and the count of frames that arrived already late.
3. **Drawer starvation** (`main_3ds.c`). Count offers dropped because the drawer was busy (`DrawFrame`, the `!busy` test) and measure signal-to-start latency (tick at `LightEvent_Signal`, subtracted from the drawer's `start`).
4. **Top-pass split** (`3ds_port/nitro/src/port_render2d.c`, `DrawEngineT`). Alongside the existing `pal`/`key` split add ticks for: the `TextBgTransparent` loop, `DecideSplits` + `LookUpArt` + `DecideBandFills`, the take/commit block, and the two flat-plane fills. Add byte counters for map and tile bytes walked by `BgKeyT` and `TextBgTransparent`.
5. **Compose causes** (`3ds_port/game/app/port_compose_pica.c`, `NitroPort_ComposeFrame`). Count composes by trigger: new scene serial, new 2D set sequence, forced, other. Split the `end` phase into: display transfer, `flight_finish`, each lock acquisition, `gxCmdQueueRun`. Publish with the same local-then-atomic pattern the phase counters already use.
6. **H-blank walk** (`3ds_port/nitro/src/port_os.c`). Time the parts outside the existing keep/dma/irq split: the per-walk refresh, the thread-switch step, the line compare scan.
7. **Boot string.** Make the "drawn 2x2 and scaled down" line say whether the mode is in use, not merely allocated.
8. **Tools.** Teach `tools/bench_report.py` the new fields, with tests.

**Deliver.** The commits; a baseline re-run on both scripts; a one-page attribution that accounts for core 0 and core 1 to within 10% each (work by thread plus idle); OFF-vs-PROFILE A/B showing the instrumentation's own cost.

**Accept when** built + skipped equals done in every sample; compose causes sum to composes; the top-pass parts sum to within 10% of the pass.

**Avoid.** Reading ticks per pixel, per vertex or per line. Adding a tracing framework. "Fixing" anything you notice while instrumenting.

**Stop if** PROFILE costs more than about 3% against OFF, or the idle probes change the ranking of stages; reduce the instrumentation first.

### P2 — Decide the baseline flags

**Premise.** `HGSS_GX3D_LISTCACHE`, `STATEDEDUP`, `FUSEHASH`, `LAZYINSERT` were kept by the Azahar campaign but are off by default. `BG3SLOT` and `HGSS_SND_ADPCM` likewise.

**Do.** Three matched A/Bs against the P1 baseline, each on both scripts: (a) the four geometry flags together; (b) `BG3SLOT` alone; (c) `SND_ADPCM` alone. For each one that passes section 2's criteria, make it the default in `tools/hgss_game.py` and `3ds_port/nitro/Makefile` (env var `0` disables it), keep the build-tag suffix logic honest, and update the flag tests in `tests/test_hgss_game.py`.

**Deliver.** Three claim sheets; the default-flip commits for the kept ones; the new baseline table.

**Accept when** for (a) the list-cache hit counters are non-zero and bounding-box scan work per built scene falls; for (b) front-region commits are non-zero and no reject bucket grows; for (c) audio share of core 0 falls or holds with 0 dropped frames.

**Avoid.** Flipping a default without its A/B. For `BG3SLOT`: it changes a shared struct layout, so the flag must reach every port object (a regression test already pins this; do not weaken it).

**Stop if** any audit or verify counter for the list cache is non-zero.

### P3 — Drawer: stop re-validating an unchanged flat field picture

**Premise.** In the field every 2D layer on the top screen is either a GPU take or proven transparent ("flat"). In that state `NitroPort_Render2DSplitIfChanged` (flat branch, near 7832 of `port_render2d.c`) calls `Render` on every pass, which re-walks every text BG's map and tiles (`BgKeyCached`, `TextBgTransparent`), re-decodes edge pixels (`DecideSplits`, `DecideBandFills`) and refills two planes. In split mode the software picture does not read the 3D image, so a new 3D scene is not a reason to redo this.

**Do.** In the flat branch only, before calling `Render`:

1. Compute `EngineSmallSignature(e, snapshot, mask, 0, 0) * 31 ^ SplitLayoutSignature(e, split)` with `mask` = the committed text BGs, exactly as the non-flat reuse branch below it does.
2. Compute `EngineVramSignature` **only if** the referenced-range signature models this frame. If it is not modelled, do not fall back to the full 864 KB hash here; take today's `Render` path.
3. Store both when a flat render completes (`RememberSplit` currently returns early for flat; extend it).
4. If both match the stored values and no committed BG's scroll register changed, return 0. The caller already republishes the retained layers.
5. In every other case call `Render` exactly as today.

Add a diagnostic mode on the existing `refHashDiag` switch: when on, always run `Render` into scratch state and compare what it would publish (quad count, quad contents, slot keys, backdrop, `has3d`, `scroll3d`, `tint3d`, `eva`/`evb`/`evy`, flat flag) with the retained values; count and log any disagreement and force the redraw.

Before coding, list every input the flat picture depends on and show each is covered by one of the two signatures or by the scroll check. At minimum: registers, palettes, OAM, VRAM bank control, per-line registers, wide windows serial, wide art serial, window circles, the `split` layout fields, and the smooth-OBJ flag. Put that list in the claim sheet.

**Deliver.** The change behind no new ini knob (it rides `refHashA`); counters for flat passes skipped, redrawn, and not-modelled; the diagnostic run; both scripts A/B'd.

**Accept when** at rest, at least 90% of top passes skip; walking, the skip rate is reported honestly whatever it is; 0 disagreements across boot → title → field → walk in diagnostic mode; map and tile bytes walked per 600 ticks fall in proportion to the skip rate.

**Avoid.** Touching the non-flat paths or engine B. Skipping when the frame is not modelled. Caching anything keyed on a pointer. Treating a scroll-only frame as unchanged.

**Stop if** the diagnostic reports any disagreement you cannot explain from the dependency list; do not ship with it merely forcing redraws.

**Follow-up, only if P1/P3 counters show scroll-only passes dominate while walking:** re-emit the quads from registers and retained per-slot take data without the key walk. Write a separate claim sheet first.

### P4 — VRAM is read live (measure, do not fix)

**Premise.** `NitroPort_Render2DTakeState` snapshots registers, palettes and OAM; the drawer reads VRAM live (`SetUpEngine`). Every hash-based skip, including P3, can race a game write.

**Do.** Nothing structural. In P3's diagnostic mode, hash the referenced range a second time at the end of the pass and count passes where it changed during the pass.

**Deliver.** The count per 600 ticks in both scripts, and one paragraph on whether P3's skip can observe a torn state.

**Avoid.** Copying VRAM per pass. Adding write tracking.

**Stop and ask if** the count is non-zero at rest.

### P5 — Compose: no redraw without new content, and explain `end`

**Premise.** About 51 of 123 composes per window have no new scene yet clear the target and re-record the whole 3D; the display thread outranks the geometry worker on core 1. About 9 ms per compose in `end` is unexplained.

**Do.** Use P1's cause counters first.

- If the non-scene composes are triggered by 2D publications that carry no change (the `publish_unchanged` path in `NitroPort_ComposePublish`): compare the published display state (quads, slot keys, scroll, brightness, blend values) with what the screen last showed, and do not mark the set as new when they are equal.
- If they are triggered by real 2D changes, leave them and report that.
- For `end`: act only on what the sub-timers show. If a lock wait dominates, shorten the hold on the other side; if the queue submit dominates, report it and stop.

**Deliver.** Cause table before and after; composes per window; built scenes per window; a capture check at fixed frames.

**Accept when** composes with no content change are zero at rest, a fade and a text box still present on time (script a field text box if the frozen scripts lack one), and built scenes/s does not fall.

**Avoid.** Caching the 3D image in a new render target. Changing the lag or late policy. Any change to the flight queue ownership.

**Stop if** the cause counters show the premise is false.

### P6 — H-blank walk on the game thread

**Premise.** About 2.5 ms per frame on hardware: 0x70 bytes × 2 engines × 192 lines copied, 192 dispatches, a compare scan; the handler itself is 0.34 ms.

**Do.** With P1's sub-timers, find the largest part. Permitted reductions, each proven on its own: skip the per-line register copy and the compare scan for an engine whose registers the handler did not write during the walk (detect by comparing the 0x70 block before and after each dispatch, or by a write flag set in the register write path if one already exists); hoist per-walk work that does not depend on the line.

**Deliver.** Sub-timer table before and after; bytes copied per frame; proof that a scene which does use per-line effects (a battle start slides lines apart) still produces identical line registers, by comparing the full line-register array against the unmodified walk in a diagnostic build.

**Avoid.** Skipping dispatches. Changing interrupt order or what the game observes. Reintroducing per-line thread switches.

**Stop if** you cannot prove equality of the line-register array in a scene with per-line effects.

### P7 — Audio mixer share

**Premise.** About 26% of core 0 at the highest priority; 98% ADPCM voices; a 64-bit interpolation per output sample; channel start logic runs for all 16 channels each call.

**Do.** In `3ds_port/nitro/src/port_sound_chip.c`, one change per commit: narrow the per-sample interpolation to 32-bit arithmetic where the value ranges allow it (state the range proof); visit only channels that are active or have a pending start. Extend the existing host differential test so each change is bit-identical to the pristine mixer over the existing vector set.

**Deliver.** Bit-identity results; `[sndprof]` mix ticks per frame before and after; dropped frames (must stay 0).

**Avoid.** Lowering the sample rate, changing interpolation quality, moving the audio thread to another core or priority.

**Stop if** bit-identity fails; do not trade exactness here.

### P8 — Geometry: remove repeated work in built scenes

Only after P2 has set the flags. Do not touch the skip policy or add pacing.

**Do.**

1. A display list that fails the hidden-list box test is scanned, then walked again in full. Either stop the scan as soon as rejection is certain, or carry its result into the normal path. Counter: words scanned by rejected attempts.
2. When interpolation is off, lighting runs before the backface cull in `stage_triangle`; move the cull first for that case only. Counter: polygons lit.
3. Report, do not change: ticks the game thread spends scanning scenes that are later skipped (from P1). If it is a large share of core 0, write it up as the next question for the owner.

**Deliver.** Host fixture results (`make port-tests`, gx3d suites) bit-identical; counters; A/B on both scripts.

**Avoid.** Batch merging, stencil or draw-order changes, index buffers, fixed-to-float changes, any new cache keyed on a pointer.

**Stop if** any gx3d fixture output changes.

## 4. Things you must not do

- Throttle, pace or skip scene production or presentation to improve a number.
- Lower quality to gain speed: wide mode, audio, fades, shadows, filters and the 60 Hz game clock stay as they are. `fps=30` is not an optimisation.
- Remove or weaken the battle GPU-BG veto, or widen GPU-BG eligibility.
- Move threads between cores or change priorities. If P1's accounting shows scheduling is the dominant problem, report it with the numbers and stop; that decision is the owner's.
- Quote an Azahar millisecond as a hardware cost, or a hardware improvement you have not been given a log for.
- Weaken a test or a golden to get a pass.
- Add diagnostics after the question they answer is settled.
